# Gather Here

Read `docs/AGENT-START.md` before planning a build or changing infrastructure.

This is a public static walkthrough and fictional prototype. The durable wedding application remains planned. Default to one wedding deployed in its owner’s accounts. Do not infer a multi-couple service or permission to move real guest data from the product name.

`site/` owns the walkthrough. `prototype/concepts/` owns the selected interactive reference. `tools/build.mjs` publishes only those two directories. `docs/` owns the public implementation handoff. Keep private conversations, credentials, real guest records, and provider exports out of this repository.

Preserve the selected design in `DESIGN.md`. Keep browser simulations visibly labeled. Never use prototype role selectors or browser storage as production authorization. Requirements and tests remain separate evidence; passing local state tests is not customer acceptance or production readiness.

For infrastructure work, read current official vendor guidance, use managed authentication, and follow `docs/rsvp-contract.md` for the first durable slice. Keep secrets in the owner’s secret manager. Do not create paid resources, alter DNS, import real guests, send messages, or launch a real wedding without scoped owner authorization.
